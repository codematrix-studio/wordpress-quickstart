# Архитектура проекта

## Назначение

Quickstart закрывает базовый цикл разработки WordPress-сайта: от самостоятельной HTML-вёрстки до интеграции в PHP-тему и создания собственных расширений. Это не дистрибутив ядра WordPress.

Репозиторий хранит собственный код и ресурсы, которые размещаются в корне установки WordPress. Ядро CMS, пользовательские загрузки, секреты и локальные конфиги в Git не включаются.

## Слои проекта

### Frontend

Каталог `frontend/` содержит HTML-страницу предварительного просмотра и SCSS-исходники. На этапе вёрстки не нужны PHP-шаблоны и активная тема. Скомпилированный CSS и общий JavaScript располагаются в ресурсах стартовой темы и используются как тестовой страницей, так и сайтом.

### Тема

Каталог `wp-content/themes/quickstart/` содержит классическую PHP-тему. Она отвечает за представление: шаблоны страниц, разметку, подключение ресурсов и поддержку возможностей WordPress.

Классическая тема выбрана потому, что позволяет напрямую переносить подготовленную HTML-разметку в PHP-шаблоны. Поддержку блокового редактора и `theme.json` можно развивать отдельно, без обязательного перехода на block theme.

### Плагины

Каталог `wp-content/plugins/` предназначен для функциональности, которая должна сохраняться при смене темы: типов записей, таксономий, метаполей, интеграций, REST API и прикладной логики. Собственные плагины хранятся в Git. Сторонние плагины, установленные только для локальной разработки, исключаются локально через `.git/info/exclude`, а не общими правилами репозитория.

MU-плагины размещаются в `wp-content/mu-plugins/`. Для их автоматической загрузки WordPress ожидает PHP-файлы в корне этого каталога.

### Конфигурация

Пароли, ключи, параметры подключения к базе данных и настройки конкретного окружения относятся к локальной конфигурации и не должны попадать в Git.

## Почему нет обязательного сборщика

SCSS компилируется Dart Sass через PhpStorm File Watchers. HTML проверяется через локальный веб-сервер. JavaScript пишется на Vanilla JS и подключается напрямую. Vite, Webpack, Gulp и npm-сборка не являются обязательными частями проекта.

## Границы ответственности

- HTML/SCSS/JS — интерфейс и поведение браузера.
- Тема — представление и вывод данных WordPress.
- Плагины — самостоятельная функциональность сайта.
- Ядро WordPress — отдельный upstream-код, не копируется в репозиторий.
