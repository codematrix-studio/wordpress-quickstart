# Безопасность и соглашения

## Входные данные

Проверяйте тип, формат и допустимые значения всех данных, поступающих от пользователя, запроса, внешнего API или настроек. Используйте специализированные функции WordPress, например `sanitize_text_field()`, `sanitize_email()` и `absint()`.

## Вывод

Экранируйте значения в момент вывода с учётом контекста:

- HTML-текст — `esc_html()`;
- HTML-атрибуты — `esc_attr()`;
- URL — `esc_url()`;
- разрешённая разметка — `wp_kses_post()`.

Не считайте ранее сохранённые данные безопасными автоматически.

## Действия и доступ

- Для операций, изменяющих данные, проверяйте nonce.
- Отдельно проверяйте права через `current_user_can()`.
- Не используйте nonce как замену авторизации.
- Для SQL-запросов используйте `$wpdb->prepare()`.

## Конфигурация

Не коммитьте пароли, ключи API, токены, дампы баз данных, пользовательские загрузки и реальные конфиги окружения.

## Стандарты кода

PHP-код темы и собственных плагинов проверяется по WordPress Coding Standards (WPCS) через PHP_CodeSniffer. Конфигурация проекта находится в корневом файле `phpcs.xml.dist`; она применяется к каталогам темы и плагина.

При локальной проверке используйте установленный PHP_CodeSniffer с WPCS:

```bash
phpcs --standard=phpcs.xml.dist
```

Автоматическая проверка не требует установленного WordPress: она анализирует исходный PHP-код и не выполняет шаблоны или хуки.

## Код

Используйте префиксы проекта для глобальных функций и хуков. Документируйте публичные функции PHPDoc на русском языке. Не добавляйте абстракции и зависимости без практической необходимости.
